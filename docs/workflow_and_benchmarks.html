The runtime workflow

Every prompt goes through the same four solid stages. The last two are conditional — a clean prompt never sees them, since there's nothing to probe and nothing to revert.

01

Prompt submitted

One text field. No manual role, tool, or resource selection required.

→
02

Role auto-detection

Keyword-matched against six agent roles. No match → an explicit low-confidence warning, not a silent guess.

→
03

Fused decision

Detector score, privilege check, digital-twin simulation, provenance trust, and behavioral anomaly blend into one risk value.

→
04 · if Block or Flag

Red-team probe

An LLM (or rule-based fallback) rewords the prompt across rounds and tests each variant against the live detector.

→
05 · if run

Unlearn

Reverts exactly that probe's calibration and memory-index changes. The live system returns to its prior state.

Fusion decision rule
risk_score > 0.70  →  BLOCK
out_of_scope and raw_injection_score > 0.40  →  BLOCK
risk_score > 0.30  →  FLAG (executes, logged for review)
otherwise  →  ALLOW

The second rule checks the raw detector score, not the blended one — a fix made after real chained-attack testing showed the blended figure alone let some genuinely out-of-scope calls through uncaught.

Stage 04 only appears on FLAG or BLOCK. An ALLOW decision has nothing to red-team — there's no conflict to probe the robustness of.

Detector accuracy benchmarks

The generalization gap is the real finding, not a rounding error. Recall stays high on the held-out set (91.7% — it rarely misses an actual attack) but precision drops to 49.8%: roughly half of what it flags as risky on qualifire is actually benign. This traces to training on a broad is_dangerous label rather than an injection-specific one — a scope decision made early in this project, not a defect discovered late.

  • FPR/FNR never move — by construction. These describe the raw detector against a fixed 0.5 threshold, independent of which extra signals are wired into the fusion decision.
  • Any single extra signal, added alone, doesn't move C-ASR — 87.2% across three different partial configurations. Adding one more weighted input isn't enough on its own to change which chained attacks get caught.
  • Combining all five signals is the one configuration that actually lowers C-ASR — 79.8%, the only real improvement over the 2-signal baseline. Utility also stays mid-pack (50.7%) rather than the highest single-signal number (63.8%, digital twin alone) — a real trade-off, not a free win.
